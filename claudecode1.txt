
❯ # Task: Implement weighted Max-Cut QAOA in PennyLane (7 nodes)

  Write a single runnable script `qaoa_maxcut.py` (plus `requirements.txt` and
  a short `README.md`) that solves the weighted Max-Cut instance below with
  QAOA on PennyLane's `default.qubit` simulator. The design decisions are
  FINAL: implement them exactly, do not substitute alternatives. If your
  results deviate from the expected values in the Validation section, report
  the discrepancy instead of changing the design to make numbers match.

  ## Instance (7 nodes, 13 weighted undirected edges)
  (0,1)=6.0, (0,4)=0.8, (0,5)=1.0, (5,6)=7.2, (1,5)=3.6, (3,5)=4.2, (4,6)=5.4,
  (2,4)=1.7, (2,6)=2.9, (3,6)=4.5, (1,3)=0.5, (1,2)=2.1, (2,3)=3.2.
  Total weight W = 43.1. Node i maps to PennyLane wire i. Note PennyLane wire 0
  is the MOST significant (leftmost) bit of basis-state indices and printed
  bitstrings.

  ## Formulation (fixed)
  - One qubit per node; spins z_i = 1 - 2 x_i (|0> -> +1, |1> -> -1).
  - Normalize weights: w~ = w / 7.2 (max weight). Use w~ inside the circuit;
  ALWAYS score cuts with the ORIGINAL weights.
  - Cost Hamiltonian, built by hand: H_C = sum over edges of 0.5 * w~_ij * (Z_i
  Z_j - I). Its diagonal equals minus the normalized cut, so we MINIMIZE
  <H_C>.
  - IMPORTANT: do NOT use qml.qaoa.maxcut. It ignores edge weights (verified:
  all coefficients come out 0.5). Do use qml.qaoa.cost_layer(gamma, H_C),
  qml.qaoa.mixer_layer(beta, H_M) and qml.qaoa.x_mixer(range(7)) for the
  layers.
  - Circuit: Hadamard on all wires, then p layers of cost_layer(gamma_k)
  followed by mixer_layer(beta_k). Parameters are packed as [gamma_1..gamma_p,
  beta_1..beta_p].
  - No symmetry fixing (all 7 qubits free).

  ## Brute-force ground truth (compute this in the script from the original
  weights)
  Enumerate all 128 bitstrings, compute cut values with the original weights.
  Derive: C_max, the set of optimal bitstrings, and the mean cut (= W/2 =
  21.55). Everything below uses these.

  ## Metrics
  - NI (normalized improvement) = (<C> - mean_cut) / (C_max - mean_cut), where
  <C> uses original-weight cut values under the output distribution.
  - P_opt = total probability of ALL optimal bitstrings (both mirror images).
  - Uniform baseline P_opt = 2/128. Do NOT use "best sampled cut" as a success
  metric (5000 shots find the optimum even from a uniform sampler); you may
  still print it.

  ## Optimization (fixed)
  - Objective: exact <H_C> (analytic expectation, no shot noise), using
  differentiable simulation (diff_method="backprop", pennylane.numpy /
  autograd) to get gradients.
  - Optimizer: scipy.optimize.minimize, method L-BFGS-B, jac supplied from
  PennyLane gradients, bounds gamma in [0, pi], beta in [-pi/4, pi/4], options
  maxiter=200, ftol=1e-9, gtol=1e-6.
  - Initialization: layerwise INTERP warm start.
    - p=1: seed from a coarse grid search over gamma in [0, pi], beta in
  [-pi/4, pi/4] (e.g. 40x40, evaluating the exact energy), then polish with
  L-BFGS-B.
    - For p -> p+1: with A = [0, a_1..a_p, 0] (a = gamma or beta vector padded
  with zeros at both ends), the new entries are a'_i = ((i-1)/p) * A[i-1] +
  ((p-i+1)/p) * A[i] for i = 1..p+1. Apply separately to gamma and beta, clip
  to the bounds, then run L-BFGS-B.
  - Sweep p = 1..10. Record for each p: energy, NI, P_opt, iterations, number
  of gradient evaluations, optimized parameters.
  - Cross-check (small p only): for p = 1..4 also run 30 random-start L-BFGS-B
  runs (uniform within the bounds, fixed seed) and report the best energy and
  the fraction of runs reaching within 1e-3 of the best; confirm INTERP matches
  the best.
  - Final depth selection must be computed by the script, not hardcoded: choose
  the smallest p in the sweep with NI >= 0.90. Expected: p = 6.

  ## Final evaluation at the selected p
  Run the optimized circuit on a shots=5000 device (fixed seed). Convert
  samples to bitstrings with wire 0 as node 0. Score each sample with the
  original weights. Report empirical <C>, NI, P_opt (empirical and exact), best
  sampled cut and its partition, and the optimal partition from brute force.
  Also print the standard error of the empirical <C>.
  ## Outputs
  Do NOT generate plots or multiple data files. Write ONE consolidated file,
  ./outputs/results.json, containing:

  - "instance": edge list with original weights, normalization constant (7.2),
  W, mean_cut, c_max, optimal_bitstrings.
  - "config": seeds, bounds, optimizer options, shots, selected_p and the
  selection rule/threshold used.
  - "sweep": list over p = 1..10 of {p, energy, NI, P_opt, iterations,
  grad_evals, gamma (list), beta (list)}.
  - "p1_landscape": {gamma_grid, beta_grid, energy (2D list)} for the p=1 grid
  search.
  - "final": for the selected p, a list over all 128 bitstrings (node 0
  leftmost) of {bitstring, cut_value (original weights), is_optimal,
  exact_prob, shot_count}, plus summary metrics (empirical and exact <C>, NI,
  P_opt, standard error, best sampled cut).
  - "uniform_baseline": same per-bitstring list for the uniform distribution
  (exact_prob and shot_count from a separate 5000-shot uniform sample, fixed
  seed).

  Keep the schema flat and documented in a short docstring at the top of the
  script, so parsing and plotting code can be written separately (histograms by
  cut value are a simple group-by on "final" and "uniform_baseline"). Also
  print a short summary table (p sweep and final metrics) to the console. Use a
  fixed random seed everywhere.

  \section*{Problem conversion}

  Each of the 7 nodes gets one qubit. With $z_i=1-2x_i$ (so
  $|0\rangle\mapsto+1$, $|1\rangle\mapsto-1$), an edge contributes
  $w_{ij}(1-z_iz_j)/2$ to the cut, so maximizing the cut means minimizing
  \[
  H_C=\tfrac12\sum_{(i,j)}\tilde w_{ij}\,(Z_iZ_j-\mathbb{I})=-\tilde C .
  \]
  The circuit starts from $|+\rangle^{\otimes7}$ and applies $p$ layers of
  $e^{-i\gamma_kH_C}$ and the $X$-mixer $e^{-i\beta_k\sum_iX_i}$, then measures
  in the $Z$ basis. PennyLane's \texttt{qaoa.maxcut} ignores edge weights, so
  $H_C$ is built by hand and passed to \texttt{cost\_layer},
  \texttt{mixer\_layer} and \texttt{x\_mixer}. Brute force over all 128 cuts
  gives a unique optimum (up to the bit flip) of $C_{\max}=34.6$.

  \section*{Normalization and bounds}

  Weights are divided by the maximum, $\tilde w_{ij}=w_{ij}/7.2\in[0.07,1]$.
  This leaves the optimal partition unchanged and puts the good values of
  $\gamma$ at order one (the $p=1$ optimum is $\gamma\approx0.94$). Final cut
  values are always computed with the original weights.

  Parameters are bounded to $\gamma\in[0,\pi]$ and $\beta\in[-\pi/4,\pi/4]$.
  The symmetry $(\gamma,\beta)\to(-\gamma,-\beta)$ allows $\gamma\ge0$, and
  $\beta\to\beta+\pi/2$ flips every bit, so $\beta$ has period $\pi/2$. The
  centered $\beta$ window keeps the small late-layer values away from its edge,
  and the optimal $\gamma$ never exceeded $2.4$, so the bounds never constrain
  the solution.

  \section*{Number of layers}

  Success is measured by the normalized improvement $\mathrm{NI}=(\langle
  C\rangle-21.55)/(34.6-21.55)$, where $21.55$ is the mean cut of a random
  assignment, and by $P_{\mathrm{opt}}$, the probability of sampling an optimal
  cut (uniform baseline $1.6\%$).

  \begin{center}
  \begin{tabular}{lccccccc}
  \toprule
  $p$ & 1 & 2 & 4 & 5 & 6 & 8 & 10 \\
  \midrule

  $P_{\mathrm{opt}}$ & 0.09 & 0.14 & 0.35 & 0.48 & 0.61 & 0.74 & 0.88 \\
  \bottomrule
  \end{tabular}
  \end{center}

  I choose $p=6$, the smallest depth with $P_{\mathrm{opt}}\ge0.6$. It reaches
  $P_{\mathrm{opt}}=0.61$, about 39 times the uniform baseline, with
  $\mathrm{NI}\approx0.90$ and only 12 parameters; deeper circuits add at most
  about $0.03$ in NI per layer.

  \section*{Optimization and iterations}

  I minimize the exact expectation $\langle H_C\rangle$ with L-BFGS-B, which
  respects the bounds and converges in few gradient evaluations. Layers are
  optimized in sequence: depth $p+1$ starts from the interpolated depth-$p$
  angles, which follow a smooth annealing-like pattern. This reached the best
  optimum at every depth, whereas single random starts did so only 20--45\% of
  the time for $p\le4$. Convergence took 12 to 60 iterations for $p\le10$
  (about 33 at $p=6$), so I cap the optimizer at 200 iterations.

  \section*{Shots and evaluation}

  The final circuit is sampled with 5{,}000 shots, and each sampled bit string
  is scored with the original weights. I report $\langle C\rangle$,
  $\mathrm{NI}$ and $P_{\mathrm{opt}}$ (counting both mirror-image optimal
  strings). The best of 5{,}000 samples is not used as a success criterion,
  since even uniform random sampling finds the optimum among 128 strings almost
  surely.

⏺ They're two measures of the same thing: how likely the p = 7 circuit is to
  output each result.

  - Dots (exact probability): computed from the simulated quantum state. Since
    default.qubit simulates the state exactly, it can return the precise
    probability of every bitstring with no randomness. This is the circuit's
    true output distribution, the same one used for the NI and P_opt values in
    the sweep table.
  - Bars (5000 shots): what you get by actually measuring the circuit 5000
    times, as real hardware would, and counting how often each result appears.
    For example, the optimal partition came up 3429 times, so its bar is
    3429/5000 = 0.686.

  The two differ only by sampling noise. The optimum's exact probability is
  0.693, but this particular run of 5000 shots happened to land on it 0.686 of
  the time. That's well within the expected scatter of about 0.0065 (one
  standard deviation, √(0.693 × 0.307 / 5000)).

  The dots are there as a check. Bars that track the dots confirm that sampling
  and bitstring decoding (wire 0 = node 0) work correctly, and that 5000 shots
  is enough for an accurate estimate. On a real quantum computer you'd only have
  the bars, because the exact probabilities can't be observed.

  Convert the input adjacency list into a graph where
  current edges become nodes, connected iff they share a vertex
  in graph
  """
  def convert_graph(graph: dict) -> dict:
      # assume each edge is given both ways in the dict

      # number each edge: lookup pair -> number
      cnt = 0
      lookup = {}
      for k in graph:
          for v in graph[k]:
              lookup[(k,v)] = cnt
              lookup[(v,k)] = cnt
              cnt += 1

      # iterate thru vertices; if two edges cohabit, add both ways
      new_graph = {e:set() for e in range(cnt)}
      for k in graph:
          for v1 in graph[k]:
              for v2 in graph[k]:
                  # two edges share a vertex in graph
                  if v1 != v2:
                      # compute their vals, then have them look up to each
  other
                      edge1 = lookup[(k,v1)]
                      edge2 = lookup[(k,v2)]
                      new_graph[edge1].add(edge2)
                      new_graph[edge2].add(edge1)

          return new_graph

  \section*{Problem 3}

  Let $T$ be a function acting on an undirected graph $G = (V,E)$ such that
  $T(G) = G'$, where $G' = (V',E')$ and

  \begin{itemize}
      \item $V'$ is the set of vertices where each vertex corresponds to
  exactly one distinct $e \in E$
      \item $E'$ is the set of edges $(p,q)$ such that for vertices $p,q \in
  V'$, the corresponding two edges in $e$ share some vertex $v \in V$
  \end{itemize}

  Let $C$ be the graph of continents and their geographic similarity
  connections given in Problem (1), and let $C' = T(C)$. Each vertex of $C'$
  thus represents a distinct edge in $C$, or a distinct two-qubit gate to be
  implemented in the corresponding circuit. Each edge of $C'$ corresponds to
  two such gates that cannot be parallelized, as they share a vertex
  (continent) in $C$.

  \underline{Claim}: The minimum necessary colors $\zeta$ to form a vertex
  coloring of $C'$ is equal to the minimum possible circuit depth $\lambda$.

  \begin{proof}

  execution, where each $l_i$ a set of two-qubit gates such that each gate in

      For any color $c_i$, if two vertices $v_1,v_2$ are both colored $c_i$,
  the corresponding two qubit gates lie in the same execution layer $l_i$ and
  thus cannot share a qubit. As such, the corresponding edges in $C$ must not
  share a vertex, so by construction of $C'$, it follows that $(v_1,v_2) \notin
  E'$. It follows that the coloring is valid, so the optimal coloring of $C'$
  uses no more than $d$ colors. Since $d$ is the depth of an arbitrary valid
  circuit, it follows that $\zeta \leq \lambda$.

      $(\geq)$ Let $k$ be the number of colors used in an arbitrary valid
  coloring of $C'$. For an arbitrary color $c_i$, all vertices assigned that
  color correspond to two-qubit gates that, by construction of $C'$ and the
  coloring rule, share no common qubit among them. Now, consider the circuit

  The three functions:
  1. convert_graph(graph) builds the line graph (one node per edge, connected
     when two edges share a vertex). It numbers each edge once, sorted the same
     way as the default circuit. For each vertex it then links every pair of
     edges that meet there. It now returns (new_graph, edges) instead of just
     the graph, so you can map node indices back to qubit pairs for drawing.
  2. chromatic_number(graph) finds the minimum number of colors by recursive
     backtracking, trying k = 1, 2, … until a valid coloring exists. Two things
     keep the search fast:
     - It colors the most-connected nodes first.
     - A node may only use a color already in use or the next new one, so it
       never tries relabelled copies of the same coloring.
  3. draw_circuit(...) draws one shaded band per color (layer) in your figure's
     two-box style. Gates in the same layer never share a qubit, but their
     connecting lines can still overlap on paper (e.g. ZZ₀₄ passing over q1–q3).
     Those gates are offset into side-by-side columns within the band.
